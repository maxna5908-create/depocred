# DepoCred для iOS

Нативный SwiftUI-проект для iPhone и iPad, iOS 16+. Исходная функциональность — Android `feature/native-android`, версия 1.0.33. iOS развивается в `feature/native-ios`.

## Сборка

На Mac с Xcode 26+:

```bash
brew install xcodegen
python3 ios/scripts/configure.py
xcodegen generate --spec ios/project.yml
open ios/DepoCred.xcodeproj
```

XcodeGen создаёт проект из отслеживаемого `project.yml`. Сгенерированный `.xcodeproj`, DerivedData и ключи не коммитятся. Проект содержит приложение, модульные тесты и UI-тесты. Сторонних исполняемых зависимостей нет; Inter и Lucide взяты из тех же ресурсов Android.

`src/lib/version.ts` — общий счётчик исходников. iOS marketing version: `1.0.BUILD_VERSION`. Номер сборки в Actions: `BUILD_VERSION.GITHUB_RUN_NUMBER.GITHUB_RUN_ATTEMPT`, чтобы повторная публикация не использовала прежний номер.

## Проверки GitHub

Workflow **Native iOS**:

1. Создаёт Xcode-проект на macOS.
2. Собирает приложение и запускает unit/UI-тесты на симуляторах iPhone и iPad.
3. Создаёт Release-архив для реального устройства без подписи. Он проверяет arm64-компиляцию, но не устанавливается на iPhone.
4. Ручная точка запуска **iOS App Store** находится в `main` и вызывает workflow из `feature/native-ios`. SHA фиксируется до проверок; подпись использует тот же код. При ручном запуске с `release=true` проверяет сертификат и профиль, подписывает IPA, валидирует и загружает его в App Store Connect.

Артефакты `depocred-ios-verification-phone` и `depocred-ios-verification-tablet` содержат логи, результаты XCTest, скриншоты и PDF-примеры (папка `store-assets` с понятными именами), сгенерированный Xcode-проект и приложение для симулятора. Подписанный IPA и dSYM появляются в `depocred-ios-app-store` только после настройки Apple-секретов.

Подготовка Apple-аккаунта: [пошаговая инструкция](docs/apple-setup.md). Тексты карточки: [App Store](store/ru-RU.md). Проверка функций: [чек-лист](docs/verification.md).

## Структура

| Каталог | Назначение |
|---|---|
| `DepoCred/Core` | Модели, формулы, взаимосвязь полей, атомарное сохранение |
| `DepoCred/UI` | SwiftUI-панели, формы, результаты, история, пояснения и настройки |
| `DepoCred/Export` | Многостраничные PDF, системная отправка и сохранение в «Файлы» |
| `DepoCred/Resources` | Иконки, launch screen, privacy manifest, лицензии |
| `Tests` | Контрольные расчёты, обратные формы, хранение и PDF |
| `UITests` | Реальные пользовательские сценарии и скриншоты |
| `scripts` | Генерация проекта, подпись, проверка профиля, загрузка |

## Расчёты и состояние

- Перенесены алгоритмы `Finance.kt`, `LeasingFinance.kt`, `ReverseForms.kt` без изменения модели расчёта. Проверяются 30 кредитных и 140 депозитных сценариев из общих Android/PWA fixtures, последовательности ввода обратного депозита, примеры заказчика для лизинга и независимые балансовые равенства.
- Кредит: прямой/обратный, аннуитет/дифференцированный, комиссии и первоначальный взнос.
- Депозит: прямой/обратный, все периоды капитализации и пополнений. Автоматически рассчитываемое поле определяется последними тремя ручными изменениями, включая очистку.
- Лизинг: аннуитетный, равномерный, убывающий график; до 12 групп в обратном расчёте; аванс в ₽/%; выкуп; отсрочка; отдельные расходы; НДС на финансирование.
- По умолчанию: Депозит, светлая тема, янтарный скин. Все пять скинов поддерживают обе темы.
- Только настройки и последние 10 явно сохранённых расчётов записываются на диск. Черновики живут в `AppModel`, сохраняются при сворачивании, исчезают при завершении процесса. После уничтожения процесса системой iOS несохранённые поля тоже очищаются.
- Каждое посещение раздела создаёт новую область прокрутки с нулевой позицией. Переключение кредитных результатов сохраняет идентичность карточки.
- `LocalStore` использует atomic write и предыдущую корректную копию. При повреждении сохраняет исходные байты и пытается восстановить резервную копию. Обновления приложения не меняют путь хранения.

## Ограничения платформы

Цифровая клавиатура iOS не имеет штатной клавиши Next: над ней расположена панель «Далее» / «Применить». Следующее доступное поле получает фокус и становится видимым. Системные окна отправки и «Файлы» используют интерфейс iOS. Размер текста масштабируется через Dynamic Type; при accessibility-размерах пары полей/показателей становятся вертикальными. Reduce Motion отключает масштабирование splash и перемещения.

Публикация в App Store требует действующего аккаунта, принятия соглашений владельцем, заполненной карточки и проверки Apple. Успешная загрузка IPA означает передачу сборки в App Store Connect, а не одобрение публикации.
