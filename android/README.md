# DepoCred Android

Нативное приложение на Kotlin и Jetpack Compose. WebView, Capacitor, браузерный
движок и сервер для работы приложения не используются. Исходная PWA остаётся
в корне репозитория. Все экраны Android находятся в `app/src/main/java/ru/depocred/app`.

## Сборка

Нужны JDK 17, Android SDK Platform 36, Build Tools 36.0.0. Минимальная версия
устройства — Android 8.0 (API 26), target SDK — Android 16 (API 36).

```bash
cd android
./gradlew testDebugUnitTest lintRelease assembleDebug
```

Версия читается из `../src/lib/version.ts`: `BUILD_VERSION=31` означает
`versionCode=31`, `versionName=1.0.31`. При обновлении увеличивать общий счётчик.

Для подписанной сборки передать переменные окружения:

| Переменная | Значение |
|---|---|
| `DEPOCRED_KEYSTORE` | Абсолютный путь к приватному хранилищу |
| `DEPOCRED_KEY_ALIAS` | `key0` |
| `DEPOCRED_STORE_PASSWORD` | Пароль хранилища |
| `DEPOCRED_KEY_PASSWORD` | Пароль ключа |

```bash
./gradlew testDebugUnitTest lintRelease assembleRelease bundleRelease
```

Результаты: `app/build/outputs/apk/release/app-release.apk` и
`app/build/outputs/bundle/release/app-release.aab`. Release требует явного ключа:
автоматической подмены debug-подписью нет. R8, удаление неиспользуемых ресурсов
и отключение отладчика включены. Сохранять `mapping.txt` для каждого релиза.

Ключ, пароли и `local.properties` не коммитить. APK и AAB не добавлять в Git.

## Соответствие исходной PWA

| PWA | Нативная реализация |
|---|---|
| Кредит: прямой расчёт | Аннуитетный и дифференцированный графики, обе комиссии |
| Кредит: обратный расчёт | Любые 2 из 3: срок, первый/ежемесячный платёж, возврат; первоначальный взнос; поиск ставки |
| Депозит: прямой расчёт | Все 7 частот капитализации, все 5 периодов пополнения |
| Депозит: обратный расчёт | Любые 3 из 4: сумма, итог, ставка, срок |
| Лизинг: прямой расчёт | Аннуитетный, равномерный и убывающий графики; аванс, выкуп, отсрочка, отдельные расходы |
| Лизинг: обратный расчёт | До 12 последовательных групп платежей, кредитный эквивалент и эффективная ставка |
| Сессии формы | Раздельные формы прямого/обратного расчёта; сохраняются при сворачивании и пересоздании Activity, очищаются при новом запуске после закрытия |
| История | Последние 10 сохранённых расчётов, фильтры, удаление, график и PDF |
| Темы | Светлая, тёмная, системная; 5 исходных акцентов; подсказки |
| PDF | Android `PdfDocument`, кириллица, цвет схемы, параметры, итоги, весь график, нумерация страниц |
| Отправка | `ACTION_SEND`, `application/pdf`, `FileProvider`, `ClipData`, временное право чтения |
| Сохранение PDF | Системный выбор папки (`ACTION_CREATE_DOCUMENT`) |
| Инфо | Сайт, почта, отправка ссылки, оценка, политика конфиденциальности |

Иконки экспортированы из того же Lucide, шрифт Inter встроен для офлайн-работы.
Палитра и размеры карточек, полей, заголовков и нижнего меню перенесены из PWA.
Системные клавиатура, выбор файла и меню отправки следуют Android.

## Расчёты и проверка

Формулы, соглашения и контрольные примеры лизинга описаны в
[docs/leasing.md](docs/leasing.md). История и PDF включают все исходные поля,
группы платежей, выкуп и обе ставки. Старые сохранённые кредиты и вклады
читаются без миграции или очистки.

`Finance.kt` сохраняет соглашения исходника: январь как первый месяц,
фиксированные 365 дней, пополнение в начале соответствующего месяца.
Комиссия вычитается из полученной суммы; `totalRepayment` обозначает сумму
платежей по графику. Переплата включает комиссию. Это не банковская оферта.

Нативный поиск ставки использует ограниченный численный метод вместо
нестабильного Newton-Raphson. Поддерживаются 0%, проверяются невозможные
параметры и сумма комиссий. В обратном расчёте депозита приоритет имеют
последние три вручную изменённых поля, включая очистку; четвёртое обновляется
при изменении источников, пополнений и капитализации. По кнопке «Рассчитать»
ставка согласуется с итоговой целью, как в PWA. В обратном кредите после суммы
и типа платежа вводятся два параметра из трёх; третий блокируется до очистки
одного из исходных полей. Автоподбор срока депозитной формы повторяет поиск
PWA в диапазоне 1–600 месяцев; ручной ввод срока поддерживает до 999 месяцев.
Остаток кредита вычисляется устойчивой формулой: на экстремальных параметрах
PWA (999 месяцев / высокая ставка) накопление ошибки могло оставить долг
непогашенным. Для этого случая проверяются независимые бухгалтерские
равенства, а для обычных сценариев — совпадение с PWA до копейки.

Эталонные данные формируются **не нативным кодом**, а исходной PWA:

```bash
# Из корня репозитория, после npm ci:
node --import tsx scripts/generate-finance-fixtures.ts
node scripts/generate-reverse-form-fixtures.mjs
cd android
./gradlew testDebugUnitTest
./gradlew connectedDebugAndroidTest  # Android-устройство или эмулятор
```

30 кредитных и 140 депозитных сценариев проверяют итоги и каждую строку
графика. Дополнительно проверяются обратные расчёты, нулевая ставка,
валидация, сериализация истории, локальное хранение и PDF. Отдельный эталон
выполняет исходные `useEffect`/solvers PWA и проверяет 39 переходов полей.
Восемь сценариев на Android проверяют интерфейс, клавиатуру, стабильность
позиции при смене платежа, обратные формы и генерацию/отправку PDF.

## Данные и обновления

Приложению не нужны разрешения, в том числе `INTERNET`, медиа и хранилище.
История и настройки находятся во внутренней директории, запись атомарная,
схема данных версионируется. Версия 2 хранит только настройки и явно сохранённую
историю. Черновики, текущий результат, инструмент и режим остаются в ViewModel
на время сеанса. При чтении версии 1 старые черновики игнорируются, настройки
и история сохраняются. Переход по главному меню сразу открывает начало раздела.
Отмена отложенной записи не считается ошибкой; финальная запись использует
последний подготовленный снимок, а не устаревшую очередь.
Повреждённые исходные байты сохраняются для
восстановления. Снимки сохранённых результатов хранятся вместе с графиком:
изменение алгоритмов в последующих версиях не меняет старый результат.

При обновлении того же `applicationId` тем же сертификатом данные сохраняются.
При удалении приложения/очистке данных локальная история удаляется.
Автоматический облачный backup отключён. PDF в кэше доступны получателям
по ограниченному URI, файлы старше 7 дней очищаются при создании отчёта.
PDF, сохранённый пользователем через системный выбор папки, остаётся там.

Данные PWA в браузерном `localStorage` изолированы от Android-приложения;
автоматического переноса браузерной истории нет.

См. `docs/google-play.md` для подготовки публикации и `docs/privacy-policy.md`
для текста политики. Приложение не публикуется автоматически.

## GitHub Actions

Workflow `Native Android` запускает тесты и сборку в отдельной ветке и PR.
Ручной запуск с `release=true` собирает подписанные файлы после настройки
трёх Repository Secrets: `DEPOCRED_KEYSTORE_BASE64` (содержимое ключа в base64),
`DEPOCRED_STORE_PASSWORD`, `DEPOCRED_KEY_PASSWORD`. Приватный файл создаётся
во временной директории runner и удаляется после сборки. Секреты не являются
частью исходников и автоматически этой задачей в GitHub не загружаются.


Публикация через GitHub: [пошаговая настройка Google Play](docs/github-play-setup.md).
